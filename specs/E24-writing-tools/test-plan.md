# E24 Writing tools — Test plan

Unit tests only (Planning/14-Testing-and-Quality.md); the real API is never called. A fake `DraftGenerator` and a fake streaming client replace Claude.

- Python (`services/core/tests/unit/writing/`): template cover letter and CV (facts only, tones, word limit, headings, ordering); AI-only kinds need AI; status; claim check (invented number, employer, skill, credential; facts accepted); cross-contamination (other employer, other address, own former employer allowed); placeholders, missing target, over limit; text and instruction bounds; AI draft labelled and checked; AI outage fallback and refusal; versions per kind and opportunity and the limit; attach copies the exact text, replaces older versions, blocks drafts with issues, other opportunity, closed approval; detach restores the default letter; remove detaches and soft deletes; Anthropic writer (adaptive thinking, no `budget_tokens`, config model, prompt contents and untrusted-data wording, refusal, empty output, API errors); key-driven provider choice; routes and error codes; SQL persistence and soft delete.
- TypeScript: api-client in-memory and HTTP, client-core hooks, web writing page and approval section, mobile writing screen (all text from the catalog).
- Manual (not in the suite): open http://localhost:3000/approvals, open an approval, "Write or tailor materials", write a cover letter, see the "AI is not configured" note, edit a sentence to name another employer and see it flagged, add the clean version, and confirm the approval screen shows it. With `ANTHROPIC_API_KEY` in `.env`, restart the backend and write an essay.
