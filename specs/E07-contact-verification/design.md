# E07 Contact verification — Design

- Config `config/defaults/verification.yaml`: `code_length`, `code_ttl_seconds`, `max_attempts`, `resend_cooldown_seconds`, `sends_per_hour`, `sms_enabled`. Public config exposes `codeLength`, `resendCooldownSeconds`, `smsEnabled`.
- `platform.one_time_codes.OneTimeCodes` (redis-coord, `cp:{env}:otp:{purpose}:{target}`): `issue` stores HMAC-SHA256(secret, target + code) with TTL; `check` returns an enum outcome (`VALID`, `INVALID`, `EXPIRED`, `LOCKED`) and counts attempts; cooldown and hourly counters use separate keys; every store failure raises `SERVICE_UNAVAILABLE` (fail closed).
- `candidate.services.verification.ContactVerificationService`: `send(user, contact)` → `VerificationChallenge(destination, expires_at, resend_after_seconds)`; `confirm(user, contact, code)` → `Profile`. Email text from the `verification.*` catalog keys, sent through the `EmailSender` port.
- API: `POST /v1/profile/contacts/{id}/verification`, `POST /v1/profile/contacts/{id}/verification/confirm` (`{code}`). Errors: 422 `code_invalid` / `code_expired`, 429 `too_many_attempts` (details `resend_cooldown`, `send_limit`, `attempts`), 409 `already_verified`, 503 `sms_unavailable` / `delivery_failed`.
- Clients: `ProfileApi.sendContactCode`, `confirmContactCode`; hook `useContactVerification` (send, confirm, resend countdown, error keys); schema `verificationCode`. Web: Verify button on unverified email contacts opens a dialog that sends the code. Mobile: Verify button opens the `profile/verify-contact` screen. In-memory demo adapter accepts `api.demo_verification_code` from config.
